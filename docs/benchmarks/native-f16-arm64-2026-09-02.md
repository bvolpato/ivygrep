# ARM64 native half conversion

[Raw trials and profile summaries](native-f16-arm64-2026-09-02.json) compare main
`7413229` with native half-to-single conversion in the vendored USearch backend.
No quantization, model weights, candidate budgets, or index format changed.

## Measurements

Neoverse V2 Linux ARM64, eight-core affinity, 50,001 generated chunks, static
embedding model, four alternating baseline/candidate trials. Both builds used
release optimization, thin LTO, and profiling symbols. A normal-release pair
confirmed the enrichment gains after the crate-version update.

| Measurement | Baseline median | Candidate median |
| --- | ---: | ---: |
| Hash vector enrichment | 1.208 s | 0.554 s |
| Neural vector enrichment after hash | 18.785 s | 8.986 s |
| Warm distinct neural query | 2.686 ms | 2.514 ms |
| Filtered neural query | 40.161 ms | 40.726 ms |

Enrichment time fell 54% for hash and 52% for neural. Search gains were smaller:
6.4% for warm distinct queries, with no demonstrated filtered-query improvement.
Every generated-corpus query retained its expected result and executed neural
retrieval when required. These are synthetic retrieval checks, not a public
relevance leaderboard.

The benchmark's 50-ms resource-sampling loop makes short foreground-index timings
too coarse: its initial medians were 353 vs 403 ms. Ten further alternating runs
using blocking subprocess timing measured 351.6 vs 347.7 ms. There is no evidence
of a foreground-indexing regression or meaningful improvement. The last
symbolized baseline trial overlapped a compilation; the normal-release pair and
precise foreground confirmation ran after compilation. The host was shared; a
soak used CPUs 0–7 and a relevance check used CPUs 16–23.

## Profiles and correctness

- `perf`, 199 Hz user-space cycles: 70.75% of enrichment samples were in USearch's
  F16 cosine metric. The conversion used software bit manipulation. The new
  AArch64 GCC/Clang path uses the compiler's `__fp16` conversion; it does not
  enable optional FP16 arithmetic. See [GCC's type documentation](https://gcc.gnu.org/onlinedocs/gcc/Half-Precision.html).
- The local hybrid-search profile also found Tantivy union traversal and document
  deserialization, allocation, and store-opening costs. The benchmark calls the
  local search API, so these costs must not be confused with daemon cache replay.
- Heaptrack recorded 6.72 million allocations and a reported 67.39M peak heap
  during fixture setup plus five seconds of local search. These are not per-query
  counts. They do not justify an unmeasured fusion/presentation rewrite.
- Futex tracing recorded 18,203 calls and 18.23 aggregate thread-seconds waiting.
  This includes ordinary Rayon worker idling, not just lock contention; no locking
  change is justified by that total alone.
- All 63,488 finite half values round-trip bit-for-bit through the persisted
  native store, including signed zeros and subnormals. The direct conversion
  check also passed under QEMU's Cortex-A53 CPU model, with baseline ARMv8-A
  code generation. All 42 vector-store regression tests passed.
- CoSQA remains below its unchanged gates: candidate nDCG@10 0.13725 and recall@20
  0.340 on 500 queries, versus required 0.14 / 0.35. This optimization does not
  resolve [issue #318](https://github.com/bvolpato/ivygrep/issues/318).

The native store remains readable without migration. Floating-point reduction
order and approximate graph construction can still change near-tied rankings;
bit-exact conversion is not a claim of identical ANN graphs.

## Reproduce

Build symbolized binaries with `CARGO_PROFILE_RELEASE_DEBUG=1` and
`CARGO_PROFILE_RELEASE_STRIP=none`. For Criterion use the equivalent
`CARGO_PROFILE_BENCH_*` variables and build `indexer_bench` with `--no-run`.
Invoke its executable with `--bench`; omitting this flag runs test mode instead
of a timed profile.

```sh
perf record -F 199 -e cycles:u --call-graph dwarf -o enrichment.data -- \
  ig --enhance-internal /tmp/public-corpus
perf record -F 199 -e cycles:u --call-graph dwarf -o search.data -- \
  indexer_bench --bench hybrid_complex_phrase_1000_files --profile-time 15
perf report -i search.data --stdio --no-inline --no-children --call-graph none
heaptrack -o search-alloc indexer_bench --bench hybrid_complex_phrase_1000_files --profile-time 5
strace -f -c -e futex indexer_bench --bench hybrid_complex_phrase_1000_files --profile-time 5
python3 scripts/bench_million_chunks.py --binary target/release/ig \
  --corpus /tmp/public-corpus --home /tmp/public-profile-home \
  --files 500 --chunks-per-file 100 --query-samples 20 \
  --enhance-hash --enhance-neural --output /tmp/profile-trial.json
```

Use fresh benchmark homes, fixed CPU affinity, the same cached static model, and
alternating binary order. Raw profile fingerprints and full trial metrics are
retained in the JSON; large native profile files are not checked into Git.
