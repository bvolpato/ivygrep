# Linux ARM64 validation — 2026-09-02

This run found and fixed test-environment failures, missing native ARM64 CI coverage,
an incorrect neural benchmark mode, and avoidable ARM64 exact-scoring cost.
It does **not** establish state-of-the-art retrieval: the public CoSQA neural gate
still fails, and the raw-code challenge stops on a query-syntax ambiguity.

The [machine-readable results](linux-arm64-2026-09-02.json) preserve binary hashes,
trial estimates, dataset identities, quality summaries, and measurement limits.
Changes are in [PR #317](https://github.com/bvolpato/ivygrep/pull/317).

## Host and scope

The host has 32 ARM Neoverse V2 cores, 123.5 GiB RAM, and Linux 6.8.0-1057-aws.
Validation used Rust 1.96.0, Python 3.12 and 3.14.5, Node 26.3.0, and pnpm 10.33.0.
The million-chunk first-results trials used Btrfs on EC2 NVMe instance storage.
Builds, microbenchmarks, and enrichment pilots used memory-backed temporary storage.

Baseline measurements use source `1f4e958f5c4d2548035013eec5efb2b2255bef36`.
The JSON distinguishes the original baseline CLI, candidate benchmark executable,
and candidate CLI; old relevance measurements are not relabeled as candidate runs.
The broad benchmark suite overlapped other validation work. The final paired scoring
experiment and three SSD indexing trials ran without other heavy jobs from this run,
but the host was not dedicated and the filesystem cache was not dropped.

Temporary Git repositories now disable commit/tag signing locally, without changing
the user's Git configuration. `test.sh` resolves the real Cargo target directory.

The neural ARM job uses release mode, matching the existing supported ARM workflow;
the dependency's ARM debug assembly limitation was not repaired here.

Windows context acceptance now checks the existing security contract: deleted-file
metadata and live-file context work, but historical-only source hydration is skipped
where Git's working directory cannot be safely anchored. The fix does not weaken
containment to make a test pass. Cross-platform CI results belong to the PR's exact
head, not to these local ARM64 measurements.

The two-minute soak is not a long-term leak test. RSS ended at 42.2 MB after peaking
at 60.1 MB; descriptors fell from 17 to 14, while threads grew from 35 to 102 as work
initialized pools. GPU execution, musl containers, and x86 emulation were not tested
locally. Linux builds with `accelerate,metal` verify portable feature handling, not
GPU acceleration.

## Exact vector scoring

The ARM64 implementation now selects NEON at runtime. Exact top-k scoring uses at
most four coarse parallel partitions on ARM64, reducing contention in USearch's
shared key lookup. The x86 AVX2 path and ranking/model configuration are unchanged.
Tests cover short, tail, unaligned, and transformer-sized vectors against a
double-precision reference, alongside the existing scalar and ranking tests.

The controlled experiment used 50,000 stored F16 vectors, 256 dimensions, and top-50
selection. Each cell averages two Criterion trial means: baseline, candidate,
candidate, baseline; each trial used 10 samples, a one-second warmup, and ten-second
measurement, with CPU affinity 0–7 and eight Rayon threads.

| Eligible vectors | Baseline mean | Candidate mean | Latency reduction |
| --- | ---: | ---: | ---: |
| 500 | 0.160 ms | 0.092 ms | 42.4% |
| 5,000 | 0.670 ms | 0.547 ms | 18.3% |
| 25,000 | 3.151 ms | 2.634 ms | 16.4% |
| 50,000 | 6.253 ms | 5.243 ms | 16.2% |

A separate single before/after pair with the host's default 32-thread scheduling
gave 42.5% lower latency at 500 vectors and 5.5% lower at 5,000; 25,000 and 50,000
were approximately unchanged (1.0% and 0.5% higher). Large-batch gains are therefore
configuration-dependent, not a general 16–42% end-to-end speedup.

The initial NEON-only attempt regressed larger parallel cases and was rejected.
Its trial data is retained in the JSON. The full 32-case baseline Criterion suite
also completed, covering indexing, embeddings, vector retrieval, and hot journeys;
its absolute timings are diagnostic because that broad run overlapped other work.

## One million chunks

Three SSD trials indexed the same generated corpus: 10,000 Rust files plus a manifest,
producing 1,000,001 chunks. These are **first-results** indexes, without hash or neural
enrichment. Each trial used a fresh index home but reused the generated corpus.

| Metric | Median across three trials |
| --- | ---: |
| First-results indexing | 7.922 s |
| Indexing throughput | 126,234 chunks/s |
| Peak process RSS | 379 MiB |
| Index size | 465 MiB |
| Distinct warm RPC query p95, 100 samples/trial | 0.616 ms |
| Warm CLI p95, 20 samples/trial | 8.001 ms |
| Process-cold CLI p95, 10 samples/trial | 17.806 ms |

Warm CLI and concurrent paths reuse queries previously issued through RPC, so they
are eligible for result-cache hits. The distinct warm RPC phase is measured before
those replays. Process-cold means a new process, not cold filesystem caches. All
synthetic needle queries found their expected file at rank one; this does not measure
general natural-language relevance.

Separate, contended tmpfs pilots took 32.54 seconds for hash enrichment and a further
631.23 seconds for static neural enrichment. These are separate readiness costs,
not part of the 7.922-second first-results figure. The old harness built neural vectors
but still sent `--hash` in its CLI phase and did not verify neural execution. Its
post-enrichment query timings are not treated as neural evidence.

After fixing the harness, a baseline-CLI rerun reused the fully enriched index and
required `neural_executed: true` on every measured query path. Distinct warm RPC p95
was 6.813 ms across 20 queries; process-cold CLI p95 was 230.286 ms across ten queries.
All expected needles ranked first. This proves neural-path execution for these
synthetic prompts, not a speedup from the new ARM kernel. Cache replays preserve
the original neural provenance; they do not imply repeated model execution.

## Retrieval quality and remaining failures

The baseline self-repository screen passed all 23 queries in each mode. Foreground
and hash-enriched nDCG@10 were 0.9261; neural was 0.9216, with all 23 neural executions
observed. Each mode had MRR 0.9565, candidate recall 0.9783, and no empty results.
This small repository-specific fixture is a regression screen, not a public ranking.
The committed candidate passed the same gates: foreground/hash metrics were unchanged,
and neural nDCG@10 was 0.9271 with all 23 executions observed. Because the indexed
source tree also changed, that small increase is not evidence of a general relevance
improvement. Both final offline backend/worktree checks passed again.

The pinned public-core profile completed 1,000 queries in each of five modes:

| Mode | nDCG@10 | MRR@10 | Recall@20 |
| --- | ---: | ---: | ---: |
| Lexical | 0.2604 | 0.2131 | 0.473 |
| Hash | 0.2638 | 0.2178 | 0.471 |
| Hybrid | 0.2642 | 0.2180 | 0.472 |
| Blended | 0.2561 | 0.2103 | 0.464 |
| Forced neural | 0.2640 | 0.2198 | 0.464 |

These are query-weighted aggregates, with one repetition, not full-corpus leaderboard
scores. Corpus sizes are 816 CodeTrans DL documents, 1,008 contest documents, 20,604
CoSQA documents, and a sampled 5,000-document CodeFeedback corpus. Public-core has
431 query-ID overlaps with the checkout-reference fit ledger and must remain
regression evidence.

**CoSQA's forced-neural gate fails:** nDCG@10 is 0.137507 against a 0.14 minimum,
and Recall@20 is 0.340 against 0.350. An independent rerun reproduced both exactly.
The deterministic-reranker diagnostic was worse (0.134181 nDCG and 0.294 recall),
so it was not adopted. No thresholds, labels, candidate budgets, or model weights
were changed. [Issue #318](https://github.com/bvolpato/ivygrep/issues/318) records
the baseline failure and diagnostic evidence.

The candidate's independent 500-query run also failed: nDCG@10 was 0.137419,
MRR@10 was 0.102270 (baseline 0.102460), and Recall@20 remained 0.340.
Eleven queries changed their rank-based quality metrics. One inspected example
reordered duplicated `get_default_args` implementations, moving the labeled document
from rank two to four. A second candidate run returned exactly the baseline aggregate
metrics, so the small first-run difference is not a demonstrated SIMD regression.
SIMD accumulation is not bitwise-equivalent to scalar math, and these runs do not
establish rank-for-rank reproducibility or fix the failing gate.

A separate 520-query fit-disjoint diagnostic gave lexical/hybrid/blended nDCG@10 of
0.2412/0.2432/0.2394 and Recall@20 of 0.4808/0.4808/0.4712. No result set was empty.
The final candidate's forced-neural run on those same 520 queries had nDCG@10 0.2497,
MRR@10 0.2000, Recall@20 0.4788, and no empty results: better rank-based scores than
the lexical baseline, but slightly lower recall. This is one run, not a significance
test or an independently established leaderboard result.
Its repository-qualified query IDs have zero overlap with the checkout-reference
ledger, but applicability to the executed model remains unverified. It is not a
certified unseen-model evaluation.

The 600-query challenge did **not** complete. A natural-language prompt containing
pasted SQL and uppercase `AND` was interpreted as malformed Boolean syntax. A
focused reproduction succeeds when the code is enclosed in a closed code fence.
Strict Boolean behavior remains unchanged; an explicit plain-text query option
needs a separate interface decision. No successful challenge score is claimed.

## Reproduction

Run from a clean checkout with model caches populated before enforcing offline mode.
Use a target directory and benchmark homes outside the indexed source tree.

```sh
CARGO_TARGET_DIR=/tmp/ig-build ./test.sh --release --e2e
CARGO_TARGET_DIR=/tmp/ig-build ./test.sh --hash-only --e2e
python3 -m unittest discover -s tests -p 'test_*.py'
./scripts/bootstrap_stress_fixtures.sh
CARGO_TARGET_DIR=/tmp/ig-build cargo test --release --locked --test stress_harness -- --ignored --test-threads 1
CARGO_TARGET_DIR=/tmp/ig-build cargo bench --locked --bench indexer_bench

python3 scripts/bench_million_chunks.py \
  --binary /tmp/ig-build/release/ig \
  --corpus /path/on/ssd/corpus --home /path/on/ssd/index-1 \
  --query-samples 100 --source-commit BUILD_COMMIT --output million-1.json

HF_HOME=/path/to/model-cache HF_HUB_OFFLINE=1 IVYGREP_MODEL_PROFILE=static \
  python3 scripts/run_current_head_benchmark.py \
  --binary /tmp/ig-build/release/ig --require-neural --output self-relevance.json

HF_HOME=/path/to/model-cache HF_HUB_OFFLINE=1 IVYGREP_MODEL_PROFILE=static \
  python3 scripts/run_public_benchmark_matrix.py \
  --binary /tmp/ig-build/release/ig --skip-build --profile public-core \
  --datasets-root /path/to/public-data --work-root /path/to/public-runs \
  --modes lexical,hash,hybrid,blended,neural --runs 1 \
  --source-commit BUILD_COMMIT --output public-core.json
```

For the paired microbenchmark, freeze the baseline and candidate benchmark executables,
then run each in its own `CRITERION_HOME` with
`RAYON_NUM_THREADS=8 taskset -c 0-7 BENCH --bench exact_filtered_vector --sample-size 10 --warm-up-time 1 --measurement-time 10`.
Repeat in baseline/candidate/candidate/baseline order. For the million-chunk neural
phase, add `--reuse-index --enhance-neural`; use a new home instead of `--reuse-index`
when measuring construction. Fetch the stress fixtures with the repository's fixture
preparation script before running the ignored tests.
