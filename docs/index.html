grep finds what you typed. ivygrep finds what you meant.

Ask your code a question in plain words. Get ranked files, line numbers, and the code itself. Indexing and search run on your machine, for you and for your coding agents.

Ask when you don’t know the name. Be exact when you do.

The first query indexes the repository. After that, a local daemon watches for changes and keeps the same index ready for every kind of search.

Recorded with ig 1.3.6 on the same ripgrep source. Rose marks primary evidence. Green marks code reached through a relationship. The budget covers the rendered pack, so headings count too.

Start from your branch

ig context "fix refresh-token races" --since main --budget 8000

The pack covers commits since the merge base with main, plus staged, unstaged, and untracked files.

Start from an error

pytest 2>&1 | ig context -

Paths in a pasted trace or issue become starting points. The output is evidence to read: it does not generate an answer or edit files.

What the agent asks for

ig_search
  query: "fix refresh-token races"
  path: "/absolute/repository/path"
  output=context_pack
  since=main
  budget_tokens=8000

What to put in your agent instructions

Use ivygrep before broad filesystem scans.
Pass the absolute active worktree path.
Use natural-language queries for concepts
and literal=true for identifiers.
For implementation, request
output=context_pack with budget_tokens=8000.

After setup, restart an open client. ig agent doctor checks the connection.

Index once. It keeps up.

Search starts before indexing finishes

Keyword and exact search come first. Background workers then add hash vectors and neural vectors.

Edits arrive on their own

The daemon watches your files and updates only what changed. A file confirmed as missing leaves the results at once.

Worktrees share one index

Worktrees reuse one base index and store only divergent chunks and tombstones. Ten worktrees do not need ten complete indexes.

Your code stays where it is.

This is everything that leaves your machine:

Source, notes, queries, resultsNothingIndexing and search run locally. There is no hosted inference.
Embeddings and indexesNothingThey live in ~/.local/share/ivygrep. ig --rm deletes one.
TelemetryNoneThere is no account and no usage reporting.
The default modelOne download33.5 MB of pinned potion-code-16m-v2 assets on first use. It runs on CPU. --hash avoids the download.
The Web UIOnly if you bind itLoopback by default, with a session token in every case. Non-loopback serving is plain HTTP: use a trusted network or a tunnel.

Install

Homebrew

brew install bvolpato/tap/ivygrep

macOS and Linux. Metal build on Apple Silicon, portable build elsewhere.

Shell installer

curl -fsSL https://raw.githubusercontent.com/bvolpato/ivygrep/main/install.sh | sh

macOS and Linux. Picks a compatible build and checks its SHA-256. CUDA is used only on Linux x86_64 with a supported GPU and runtime.

WinGet

winget install --id BrunoVolpato.ivygrep --exact

Windows. WinGet updates can lag GitHub releases.

PowerShell installer

irm https://raw.githubusercontent.com/bvolpato/ivygrep/main/install.ps1 | iex

Windows. Installs the latest published version, or the one that IVYGREP_VERSION names.

CUDA and Metal only speed up optional transformer models. ig hardware shows your build and the matching install command.
