# Governance

ivygrep uses maintainer-led governance. Project direction stays public through
issues, discussions, pull requests, changelog entries, and benchmark evidence.

## Roles

- **Contributors** report problems, propose changes, review work, write code, or improve docs.
- **Reviewers** provide recurring technical review in areas they understand.
- **Maintainers** set release scope, merge changes, manage security reports, and enforce community standards.

Current maintainer: [Bruno Volpato](https://github.com/bvolpato).

## Decisions

Small changes proceed through pull-request review. Large changes start with an
issue or discussion covering user value, design, compatibility, and validation.
Maintainers decide when consensus is incomplete, documenting rationale in
public project history.

Performance and relevance decisions require comparable evidence. Local-first
operation, offline hash search, portability, and user privacy are project
constraints.

## Becoming a reviewer or maintainer

Sustained, constructive contributions can lead to reviewer or maintainer
invitations. Reliability, technical judgment, respectful collaboration, and
care across platforms matter more than commit count.

## Releases and security

Maintainers cut releases after required checks pass. Security fixes may use a
private advisory and coordinated disclosure before public review.

Community behavior follows [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Security
reports follow [SECURITY.md](SECURITY.md).
